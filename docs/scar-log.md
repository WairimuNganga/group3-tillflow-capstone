# Scar Log — DRI: ALL

> Log every incident/near-miss/fix here **as it happens** — do not backfill. Columns: date, what broke, blast radius, fix, follow-up owner.

| Date | What broke / was found | Blast radius | Fix | Follow-up owner |
|---|---|---|---|---|
| 2026-09-09 | **ALB access logs cannot use SSE-KMS.** The G0 design specified SSE-KMS on all S3 buckets. ALB log delivery only supports SSE-S3 (AES256) — applying the shared CMK to the log bucket would not error at apply time, log delivery would just silently stop, destroying the edge audit trail (threat model T8.4) with no signal | Would have been discovered at G1 or later as "why are there no ALB logs?", after the audit trail had already been missing for an unknown period | Dedicated `devops-g3-alb-logs-<account_id>` bucket on SSE-S3; every other bucket keeps the shared CMK. Deviation documented in [ADR-003](adr/ADR-003-object-storage.md) | Lwam |
| 2026-09-09 | **"Daraja-only egress" was not implementable as written.** T2.4 claimed SG egress rules would restrict outbound traffic to Daraja. Security groups filter by CIDR/prefix list, not hostname, and Daraja publishes no stable IP range or AWS prefix list | Design-stage only — caught in G0 mentor review before any Terraform was written. Had it shipped, the threat model would have claimed a control that did not exist | Reduced to what the primitives allow (VPC endpoints, no internet egress for three of four services, 443-only for `payments`, flow-log alerting); residual any-host HTTPS egress explicitly accepted as AR-7 rather than claimed as controlled | Lwam |
| 2026-09-09 | **RDS Proxy does not provide per-service connection quotas.** T4.6 and [ADR-002](adr/ADR-002-database.md) both claimed `MaxConnectionsPercent` would stop one service starving another. It sizes the proxy's target pool against the instance; it is not a per-credential limit | Design-stage only. Would have surfaced as a real noisy-neighbour outage under load at G3, with the "mitigation" already documented as in place | Containment moved to bounded application pools, `statement_timeout` / `idle_in_transaction_session_timeout` per service role, and a connection-borrow latency alarm for detection | Lwam |
| 2026-09-09 | **Internal routing contradicted itself.** T2.1 restricted the ALB to VPC Link traffic only, while T3.2 routed `commission → payments` through that same ALB from the commission SG. Both could not be true | Design-stage only. Would have produced either an SG exception quietly reopening the ALB to in-VPC callers, or a broken internal call path at G2 | External traffic via API Gateway → VPC Link → internal ALB; internal calls via ECS Service Connect. Service identity verified at the application layer, not by source IP | Lwam / Hunter |
| 2026-09-09 | **Availability Zone mismatch caught before apply.** Early design notes used `us-west-1a` + `us-west-1b`, but the target account supports `us-west-1a` + `us-west-1c` | Would have failed subnet creation during the first G1 `terraform apply` | Terraform defaults and ADRs now pin `us-west-1a` + `us-west-1c` | Lwam |
